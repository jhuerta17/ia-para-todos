# Workshop Checklist

> **DRAFT:** Proposed lifecycle checklist. Untested — revise after the first pilot workshop.

One checklist covering the complete workshop lifecycle, so any trained volunteer can organize a session without relying on the founder. Each phase lists owner, inputs, and done criteria.

## Phase 1 — Identify and contact a host (weeks 4–6 before)

- [ ] Identify a candidate host organization (see [outreach-process.md](outreach-process.md)).
- [ ] Send introductory outreach using [partnership-outreach.md](../../templates/partnership-outreach.md).
- [ ] Explain the educational mission: free, beginner, Spanish-first, nonsectarian, non-commercial.
- [ ] Confirm: interested audience, expected attendance (pilot target: 10–20), preferred dates/times.
- [ ] **Done when:** a named contact at the host agrees in principle to a specific date.

## Phase 2 — Confirm venue and responsibilities (weeks 2–4 before)

- [ ] Assess the venue with [venue-assessment.md](../../templates/venue-assessment.md) (internet, seating, accessibility, projector, outlets, audio, capacity, emergency exits).
- [ ] Agree in writing (email is fine) who provides what — see [venue-requirements.md](venue-requirements.md).
- [ ] Establish responsibilities for insurance and participant safety: who holds liability coverage, who is the on-site safety contact, where are exits and first aid.
- [ ] Confirm outreach plan: how the host will announce (bulletin, chat groups, announcements) and in which language.
- [ ] **Done when:** venue walkthrough complete and responsibility split documented.

## Phase 3 — Recruit and prepare volunteers (weeks 1–3 before)

- [ ] Recruit roles per [volunteer-onboarding.md](volunteer-onboarding.md): lead facilitator, assistant facilitator(s), welcome volunteer, tech support (can combine roles for small pilots).
- [ ] Confirm every volunteer has read the [facilitator-guide.md](facilitator-guide.md) and the workshop's facilitator notes.
- [ ] Hold a 30-minute prep call or meeting: assign roles, walk the agenda, test demos.
- [ ] **Done when:** every role has a named, confirmed person who has practiced the material.

## Phase 4 — Prepare materials (week before)

- [ ] Print: exercise sheets, take-home summaries, anonymous feedback forms ([workshop-feedback.md](../../templates/workshop-feedback.md)), extra blanks.
- [ ] Pack kit: hotspot + charger, demo phone + charger, adapters, extension cords, speaker, markers, tape, name tags (first names only, optional).
- [ ] Test all curriculum prompts on the demo phone (AI responses change over time).
- [ ] Record expected costs in [budget-template.md](budget-template.md).
- [ ] **Done when:** kit packed, prints counted (attendance estimate + 20%), prompts tested.

## Phase 5 — Conduct the workshop (day of)

- [ ] Arrive 45 minutes early; test projector, audio, Wi-Fi, hotspot.
- [ ] Set up welcome table: sign-in by **headcount only** (no names required), materials, seating in pairs.
- [ ] Deliver per the workshop `curriculum.md`; assistant tracks time per block.
- [ ] Protect privacy live: fictional examples only; intervene kindly if real data appears on screens.
- [ ] Note attendance count, completion signals, and anything that got stuck.
- [ ] **Done when:** session delivered, headcount recorded, room restored.

## Phase 6 — Feedback and follow-up (days 1–7 after)

- [ ] Collect anonymous feedback forms before people leave (never take names).
- [ ] Thank the host within 48 hours; share what happened in aggregate (attendance count, what worked).
- [ ] Debrief volunteers within a week; record observations in [pilot-retrospective.md](../../templates/pilot-retrospective.md).
- [ ] Enter actual costs and outcome signals per [impact-measurement.md](impact-measurement.md).
- [ ] Store any paper forms **outside this public repository**; commit only aggregate, anonymous learnings.
- [ ] **Done when:** host thanked, costs/outcomes logged, curriculum improvements filed as issues.
