# Contributing to IA Para Todos

Thank you for your interest in contributing! IA Para Todos is a community education initiative, and contributions of many kinds — not just code — move the mission forward.

> **Idioma / Language:** Contributions in Spanish and English are both welcome. Participant-facing content is Spanish-first; organizational docs may be in either language, with translation encouraged.

## Project stage

This repository is in **Part 1 of a seven-part setup**: structure, bilingual READMEs, and documentation conventions only. Organizational docs, curricula, operations guides, and automation arrive in later phases. Early contributions most helpful right now:

- Feedback on the mission framing and bilingual READMEs.
- Translation improvements (Spanish ↔ English).
- Suggestions for the planned documentation structure.

## Ways to contribute (as the repo grows)

- **Documentation** — fix errors, improve clarity, add examples.
- **Translations** — Spanish ↔ English translation of docs and curricula.
- **Curriculum feedback** — review workshop outlines once published.
- **Outreach ideas** — connections to community organizations, libraries, or venues.
- **Accessibility** — improve readability and accessible formats.

> A code of conduct, issue templates, and pull request template will be added in a later setup phase. Until then, be kind and constructive: assume good faith, welcome beginners, and focus feedback on the work.

## How to contribute

1. **Open an issue** describing the proposed change or suggestion.
2. **Fork the repository** and create a branch from `main` with a descriptive name (e.g., `readme-clarify-mission`).
3. **Make your change**, following the documentation conventions below.
4. **Open a pull request** with a clear description of what changed and why.

Small fixes (typos, broken links) may skip step 1.

## Documentation conventions

Follow the conventions in the [documentation index](docs/README.md):

- **Descriptive Markdown:** ATX headings (`#`), fenced code blocks with language tags, tables for comparisons.
- **Relative links:** link files relatively (e.g., `organization/mission-vision.md`), never with absolute URLs to the repo.
- **Status labels:** mark provisional content explicitly —
  `> **DRAFT:**` (untested/provisional),
  `> **DECISION NEEDED:**` (choice not yet made),
  `> **VERIFY:**` (fact needing an official source).
- **Spanish-first participant content:** anything learners read comes in Spanish first; English versions follow where feasible.
- **No invented details:** never add partner names, dates, statistics, contact details, or organizational facts that have not been established. Use clearly marked example placeholders such as `contact@example.org`.

## Privacy rules (mandatory)

This is a **public repository**. Never include in any issue, PR, or commit:

- Participant names, contact details, survey responses, or photos.
- Private volunteer or partner contact information.
- Passwords, credentials, API keys, tokens, or secrets.
- Financial account information or confidential agreements.

## Questions

Open an issue if you are unsure where your contribution fits. There are no bad questions here.
